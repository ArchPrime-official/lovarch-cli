> remains, then a single tag push triggers the full release pipeline.

## TL;DR — to ship v0.1.0

Estimated time: **~20 minutes** of manual setup, then ~10 minutes of
automation watching.

```bash
# Step 1 (5 min): PyPI account + first manual upload to reserve the name
```

## Step-by-step details

### 1. PyPI account + reservation

1. Go to https://pypi.org/account/register/
   - Username: choose (e.g. `pablo_archprime` or `lovarch`)
   - Email: pablo@archprime.io
   - **Enable 2FA** (mandatory for upload now)
2. Verify the email
3. **Reserve the project name** by doing one manual upload from your machine
   (otherwise the first automated upload may fail if the name isn't owned):

```bash
cd /Users/pablo/lovarch-cli
git checkout main && git pull
# Bump to 0.1.0 first (or keep beta.1 for the reservation upload — your call)
python -m pip install --upgrade build twine
python -m build
twine upload dist/*
# Paste your PyPI password / token at the prompt
```

4. After the upload lands, verify:

```bash
pip install lovarch-cli==0.1.0    # or whatever you uploaded
lovarch --version
```

### 2. PyPI token for automation

1. https://pypi.org/manage/account/token/ → "Add API token"
2. **Scope**: `Project: lovarch-cli` (only works AFTER step 1 reservation)
3. Token format: `pypi-AgENd...` — copy once, it's not shown again

```bash
gh secret set PYPI_API_TOKEN --repo ArchPrime-official/lovarch-cli
# Paste the token when prompted
```

### 3. GitHub PAT for the Homebrew tap

The auto-bump workflow needs to open PRs in `ArchPrime-official/homebrew-lovarch`,
which the default `GITHUB_TOKEN` can't reach (it's scoped to the current repo).

1. https://github.com/settings/personal-access-tokens/new
2. Name: `lovarch-cli homebrew bump`
3. Expiration: 1 year
4. **Repository access**: Only select repositories → `homebrew-lovarch`
5. **Permissions** (Repository):
   - Contents: Read and write
   - Pull requests: Read and write
   - Metadata: Read (auto-granted)
6. Generate, copy the token

```bash
gh secret set HOMEBREW_TAP_TOKEN --repo ArchPrime-official/lovarch-cli
# Paste the github_pat_... token
```

### 4. Cut the v0.1.0 release

```bash
cd /Users/pablo/lovarch-cli

# Bump version (also bump SAMPLE_RELEASE_TAG if you re-uploaded the sample)

git commit -am "chore: bump v0.1.0"
git tag v0.1.0

```

### 5. Watch the automation

Open three browser tabs:

1. **PyPI publish**: https://github.com/ArchPrime-official/lovarch-cli/actions/workflows/publish-pypi.yml
2. **GitHub Release attach**: https://github.com/ArchPrime-official/lovarch-cli/actions/workflows/attach-to-release.yml
3. **Homebrew bump PR**: https://github.com/ArchPrime-official/homebrew-lovarch/pulls

Expected outcomes within 5-10 minutes of the tag push:

- ✅ `publish-pypi.yml` run succeeds → `lovarch-cli 0.1.0` visible at
  https://pypi.org/project/lovarch-cli/
- ✅ `attach-to-release.yml` creates the GitHub Release v0.1.0 with
  `lovarch_cli-0.1.0-py3-none-any.whl` + `lovarch_cli-0.1.0.tar.gz` attached
- ✅ `bump-homebrew-formula.yml` opens a PR in `homebrew-lovarch` titled
  "bump: lovarch-cli 0.1.0" with the new SHA256

### 6. Merge the homebrew bump PR

```bash
gh pr list --repo ArchPrime-official/homebrew-lovarch
gh pr view <N> --repo ArchPrime-official/homebrew-lovarch
# Sanity check the SHA256 matches the released tarball
# CI must be green (brew install + test + audit)
gh pr merge <N> --repo ArchPrime-official/homebrew-lovarch --squash --delete-branch
```

After merge:

```bash
brew untap archprime-official/lovarch  # if previously tapped to beta
brew tap archprime-official/lovarch
brew install lovarch-cli               # → 0.1.0
lovarch --version
```

## If something goes wrong

### PyPI upload fails with 403/forbidden

→ token scope mismatch. Generate a new token scoped to `Project: lovarch-cli`
(or, if first upload, `Entire account` temporarily). Then:

```bash
gh secret set PYPI_API_TOKEN --repo ArchPrime-official/lovarch-cli
```

Re-trigger by re-tagging:

```bash
git tag -d v0.1.0 && git push origin :v0.1.0
git tag v0.1.0 && git push origin v0.1.0
```

### Homebrew bump PR not created

→ `HOMEBREW_TAP_TOKEN` missing or wrong scope. The workflow skips
gracefully (you'll see a `::notice::` in the run). Fix:

```bash
# Verify the secret exists
gh secret list --repo ArchPrime-official/lovarch-cli | grep HOMEBREW
# If missing, set it (see Step 3)
```

Then re-run manually:

```bash
gh workflow run bump-homebrew-formula.yml \
  --repo ArchPrime-official/lovarch-cli \
  --ref v0.1.0
```

### Wheel upload + GitHub Release attach disagree

Both workflows independently build the wheel. If their SHA differs:

```bash
# Download both
gh release view v0.1.0 --repo ArchPrime-official/lovarch-cli --json assets --jq '.assets[].name'
pip download lovarch-cli==0.1.0 --no-deps
shasum -a 256 lovarch_cli-0.1.0-py3-none-any.whl   # twice from both sources
```

They should match. If not, the build is non-deterministic — open an issue
(setuptools / hatchling rebuilds with different timestamps in zip; pin
`SOURCE_DATE_EPOCH` in the workflow as a fix).
